# 张量布局（Layout）复合的数学原理与手稿推导总结

本文档汇总了关于三层 GPU 硬件张量布局（Global $\to$ Tile $\to$ Warp $\to$ Thread/Reg）复合的完整理论体系、命名规范以及两页手算推导笔记的逐行还原。

---

## 一、 原始 Layout 的语义化重命名

为了摆脱 `Layout A / B / C` 这种缺乏物理层级语义的代号，我们按照**硬件映射粒度（从宏观分块到微观线程/寄存器）**对三个原始布局进行重命名。

目标问题：将一个全局形状为 `(128, 128)` 的二维矩阵（$M = 128, N = 128$）映射到 GPU 的三个物理硬件轴上：
- `W`（即 `@warp_id`）：Warp 编号（共 4 个 Warp）
- `L`（即 `@laneid`）：Warp 内的线程通道号（0 ~ 31，共 32 个线程）
- `R`（即 `@reg`）：单线程私有的寄存器编号（0 ~ 127，共 128 个寄存器）

| 原代号 | 语义化重命名 | 中文名称 | 映射关系（Domain $\to$ Codomain） | 原始表达式（`Shape : Stride`） |
| :--- | :--- | :--- | :--- | :--- |
| **Layout B** | **`Block2Tile`** | **全局分块布局** | 全局逻辑元素 $\to$ Tile 块坐标 | `(8, 16, 16, 8) : (1@m_tile, 0, 1@n_tile, 0)` |
| **Layout C** | **`Tile2Warp`** | **宏观 Warp 分配布局** | Tile 块坐标 $\to$ Warp 硬件轴 | `(8@m_tile, 4@n_tile, 4@n_tile) : (0, 0, 1@warp_id)` |
| **Layout A** | **`InTile2Thread`** | **微观块内线程/寄存器布局** | Tile 内部坐标 $\to$ Lane 与 Reg 轴 | `(2, 8, 4, 2) : (2@reg, 4@laneid, 1@laneid, 1@reg)` |

### 维度归属解析（M 树与 N 树）
全局 `(128, 128)` 在 `Block2Tile` 中被切分为 `(8, 16, 16, 8)`：
- **前两个维度 `(8, 16)` 属于 $M$ 轴**（$8 \times 16 = 128$）：其中 `8` 是块间坐标 `m_tile`，`16` 是块内坐标 `m_in`（进一步被 `InTile2Thread` 拆成 `(2, 8)`）。
- **后两个维度 `(16, 8)` 属于 $N$ 轴**（$16 \times 8 = 128$）：其中 `16` 是块间坐标 `n_tile`（进一步被 `Tile2Warp` 拆成 `(4, 4)`），`8` 是块内坐标 `n_in`（进一步被 `InTile2Thread` 拆成 `(4, 2)`）。

## 二、 两种本质不同的 Layout 复合运算

在将上述三个 Layout 合并为一个最终 Layout 的过程中，实际上包含了**两种数学本质截然不同的复合算子**：

### 1. 串行函数复合：`compose`（对应 `Block2Tile` 与 `Tile2Warp` 的复合）
- **数学本质**：经典的函数复合 $f_{\text{Tile2Warp}} \circ f_{\text{Block2Tile}}$（变量代换与重塑）。
- **连接机制（Codomain $\to$ Domain 串接）**：前一个 Layout 的**输出轴**（`@m_tile`, `@n_tile`），直接作为后一个 Layout 的**输入变量**。
- **计算法则**：
  1. **同构拆分（Reshape）**：`Block2Tile` 输出的 `n_tile` 维度大小为 `16`，而 `Tile2Warp` 接收两个大小为 `4` 的 `@n_tile` 维度，因此将 `16` 拆分为 `(4, 4)`。
  2. **线性代换（Substitute）**：用 `Tile2Warp` 的步长 `(0, 0, 1@warp_id)` 替换对应的 `@m_tile` 和 `@n_tile`。
- **关于 `0` 步长的合法性**：在此中间阶段，步长为 `0` 是完全合法的一等公民，代表**降维投影（Projection）或广播（Broadcasting）**——即这些维度上的元素全部归属于同一个 Warp 处理，不产生跨 Warp 偏移。

### 2. 正交嵌套与张量积填充：`nest` / `tensor_product`（对应嵌入 `InTile2Thread` 并补齐 `0`）
- **数学本质**：**正交补空间直和映射（Direct Sum） + 混合基数张量积（Tensor Product）**。
- **连接机制（正交维度互补）**：`InTile2Thread` **不是**作用在 `Block2Tile` 的输出上，而是作用在被 `Block2Tile` 忽略（投影为 `0`）的块内微观维度 `m_in (16)` 和 `n_in (8)` 上。
- **计算法则（两步走）**：
  1. **微观子树嫁接**：将块内的 `16` 拆为 `(2, 8)` 填入 `(2@reg, 4@laneid)`；将块内的 `8` 拆为 `(4, 2)` 填入 `(1@laneid, 1@reg)`。
  2. **消除宏观 `0`（无 0 铁律与体积累乘）**：
     - **为什么不能有 `0`**：最终映射到互斥物理存储（`@reg`）时，绝不能保留未分配的 `0` 步长，否则同一线程的不同 Tile 数据会覆写同一个寄存器。
     - **计算微观体积（Footprint）**：将 `InTile2Thread` 中所有绑定到 `@reg` 的维度大小（Size）相乘。这里 `m_in` 的低位 size 为 `2`（步长 `2@reg`），`n_in` 的高位 size 为 `2`（步长 `1@reg`），单线程处理 1 个 Tile 消耗的基础寄存器体积为：
       $$V_{\text{micro\_reg}} = 2 \times 2 = 4\text{ (@reg)}$$
     - **宏观步长累乘进位**：宏观层面未分配给 `Warp` 或 `Lane` 的剩余 `0` 维度（即 `m_tile` 的 `8` 和 `n_tile` 内层的 `4`，共 $8 \times 4 = 32$ 个 Tile），必须由单线程的寄存器线性排开。外层步长必须从基础体积 `4@reg` 开始依次乘以维度大小。

## 三、 两页手稿推导过程的逐行还原与对比

手稿中通过两种不同的路径推演了上述复合过程，分别对应了**“显式保留块内轴名（自底向上）”**与**“利用 0 步长占位（自顶向下）”**两种思维模型。

### 推导方式一（第一页手稿）：显式标记块内轴（`m_in`, `n_in`），先嵌入微观再复合宏观

在第一页中，为了防止搞混哪些维度是块间、哪些是块内，你将 `Block2Tile` 的块内步长也赋予了显式名称 `1m_in` 和 `1n_in`：

1. **定义全命名的 `Block2Tile`（原 B）**：
   ```text
   (128, 128)
   (8, 16, 16, 8) : (1 m_tile, 1 m_in, 1 n_tile, 1 n_in)
   ```
2. **先代入微观 `InTile2Thread`（原 A），替换 `m_in` 和 `n_in`**：
   - 将 `(2, 8, 4, 2) : (2r, 4l, 1l, 1r)` 代入第二个维度 `16 (m_in)` 和第四个维度 `8 (n_in)`：
   ```text
   Shape  = (8, (2, 8), 16, (4, 2))
   Stride = (1 m_tile, (2r, 4l), 1 n_tile, (1l, 1r))
   ```
   - 去括号展平为 6 个维度：
   ```text
   = (1m, 2r, 4L, 1 n_tile, 1L, 1r)
   ```
3. **再引入宏观 `Tile2Warp`（原 C），拆分 `16 n_tile`**：
   - 写下 `(8m, 4n, 4n) : (0, 0, 1w)`，识别出需要将大小为 `16` 的 `n_tile` 拆成 `(4, 4) n_tile`。
   - 批注：*“$\Rightarrow$ 很正确的写对了，另一种写法？”*
4. **底部展平对齐，推导寄存器步长 `4R` 与 `16R`**：
   ```text
   Shape  :   8  ,   2  ,  8  ,    16   ,  4  ,  2
   Stride :  1m  ,  2R  , 4L  ,    1N   , 1L  , 1R
                    --                      --        (← 下划线标出 2R 和 1R，基础体积 = 2 * 2 = 4R)
                                   4R                 (← 1N 的内层补为 4R)
             16R                 (4, 4)               (← 16 拆为 (4, 4)，跨过内层 4 个 4R 后，1m 变为 4 * 4 = 16R)
              ~                    ~
             16R                  0  1W               (← (4, 4) 对应 (0, 1W)，其中的 0 即为 4R)
   ```

---

### 推导方式二（第二页手稿）：“另一种计算方式”——保留 `0` 步长，先复合宏观再填补微观

第二页严格遵循原始定义中的 `0` 步长，先做宏观复合，再逐步把 `0` 拆开替换：

1. **先复合 `Block2Tile`（原 B）与 `Tile2Warp`（原 C）**：
   - 原始 `Block2Tile`：`(8, 16, 16, 8) : (1 m_t, 0, 1 n_t, 0)`
   - 原始 `Tile2Warp`：`(8m, 4n, 4n) : (0, 0, 1w)`
   - 将第三个维度 `16` 拆为 `(4^n, 4^n)` 并代入，得到只含 `1w`、其余全为 `0` 的宏观骨架：
   ```text
   Shape  = (8^m, 16, (4^n, 4^n), 8)
   Stride = (0  ,  0, (0  , 1w ), 0)
   ```
2. **分两步嵌入微观 `InTile2Thread`（原 A），替换块内的两个 `0`**：
   - 写出 `(2, 8, 4, 2) : (2R, 4L, 1L, 1R)`，标注前两项乘积 `2 * 8 = 16`，后两项乘积 `4 * 2 = 8`。
   - **第一步（替换末尾的 `8`）**：拆为 `(4, 2)`，步长 `0` 替换为 `(1L, 1R)`：
     ```text
     (8, 16, (4, 4), (4, 2)) : (0, 0, (0, 1W), (1L, 1R))
     ```
   - **第二步（替换第二项 `16`）**：拆为 `(2, 8)`，步长 `0` 先展开为 `(0, 0)` 再替换为 `(2R, 4L)`：
     ```text
     (8, (2, 8), (4, 4), (4, 2))
     = (0, (0, 0), (0, 1W), (1L, 1R))
     = (0, (2R, 4L), (0, 1W), (1L, 1R))
     ```
3. **填补剩余的两个宏观 `0`——推导出 ① 和 ② 两个分支**：
   此时还剩第一项（size `8`）和第三项左半边（size `4`）为 `0`。手稿中向下画箭头 $\Downarrow$ 给出了两种填法：
   - **分支 ①（从右往左补 `0` / $N$ 轴优先）**：
     ```text
     (16R, (2R, 4L), (4R, 1W), (1L, 1R))   --> 批注：“靠右，越在内存内”
     ```
     *计算过程*：靠右的 `(4, 4)` 中的 `0` 先拿基础体积 `4R`；最左边 size 为 `8` 的 `0` 跨过这 4 个块，拿 $4 \times 4 = 16\text{R}$。
   - **分支 ②（从左往右补 `0` / $M$ 轴优先）**：
     ```text
     (4R, (2R, 4L), (32R, 1W), (1L, 1R))
     ```
     *计算过程*：如果让最左边 size 为 `8` 的 `0` 先拿基础体积 `4R`；那么中间 `(4, 4)` 中的 `0` 就必须跨过这 8 个块，拿 $8 \times 4 = 32\text{R}$。

## 四、 核心数学问题：为什么分支 ① 比分支 ② 更优？（拓扑保距定理）

手稿第二页底部的分支 **① (`16R, ..., 4R`)** 和分支 **② (`4R, ..., 32R`)** 揭示了一个核心结论：**在纯集合论双射（Bijection）意义下，① 和 ② 都是绝对合法的**——两者都恰好将 $16384$ 个元素无重叠、无遗漏地映射到了 $4\text{ Warps} \times 32\text{ Lanes} \times 128\text{ Regs}$ 中。

但编译器和硬件标准唯一选择 **分支 ①**，原因在于**空间局部性（Spatial Locality）与拓扑保距映射**：

1. **“同树看底牌”法则（以微观 `1@reg` 锚定连续主轴）**：
   - 我们将全局维度还原为正交的 **$M$ 轴树 `(8, (2, 8))`** 和 **$N$ 轴树 `((4, 4), (4, 2))`**。
   - 在微观 `InTile2Thread` 中，$N$ 轴最内侧叶子节点拿到了最小步长 **`1@reg`**，而 $M$ 轴叶子拿到了 **`2@reg`**。这在物理上确立了 **“$N$ 轴是寄存器内的连续主轴（Row-Major / N-Major）”**。
2. **最小化跨块边界跳跃距离（Jump Distance）**：
   - 当沿着逻辑 $N$ 轴连续遍历、跨越微观块边界触发进位到宏观 `n_tile` 时，物理寄存器地址的跳跃差分为：
     $$\Delta f_N = c_{n\_\text{macro}} - D_{n\_\text{micro}} + 1$$
   - 若选择 **分支 ①（同树优先）**：将最小可用宏观步长 `4R` 分给同属 $N$ 轴的 `(4, 4)`，跨块边界时的地址跳跃被控制在最小范围，维护了 $N$ 轴从微观到宏观的一致连续性。
   - 若选择 **分支 ②（异树优先）**：把巨大的 `32R` 分给 $N$ 轴，会导致 $N$ 轴在块内步长为 `1`（紧挨着），一旦跨块却突然跳跃 `32` 个寄存器，撕裂了逻辑轴的拓扑度量。

## 五、 最终 TIRx 代码表示与工程实现建议

### 1. 最终 Composite Layout 的 TIRx 表达
```python
from tvm.tirx.layout import TileLayout, S

# 嵌套元组形式（保留 M=(8,(2,8)), N=((4,4),(4,2)) 的层次结构）
composite_layout = TileLayout(
    S[
        (8, (2, 8), (4, 4), (4, 2)) :
        (16@reg, (2@reg, 4@laneid), (4@reg, 1@warp_id), (1@laneid, 1@reg))
    ]
)

# 等价的一维展平形式（Flatten）
composite_layout_flat = TileLayout(
    S[
        (8, 2, 8, 4, 4, 4, 2) :
        (16@reg, 2@reg, 4@laneid, 4@reg, 1@warp_id, 1@laneid, 1@reg)
    ]
)
```

### 2. TVM / TIRx Python 前端 API 设计建议
这套推导完全可以在 **Python 前端**作为轻量级布局代数工具实现（无需修改底层 C++ TIR AST 节点），对标 NVIDIA CuTe 的布局代数算子：

| 算子功能 | 推荐 Python API 命名 | 对应 NVIDIA CuTe 算子 | 职责描述 |
| :--- | :--- | :--- | :--- |
| **宏观串行复合** | `layout_b.compose(layout_c)` 或 `chain()` | `composition(C, B)` | 将前者的输出轴匹配并替换为后者的输入域，支持维度自动拆分，保留 `0` 步长。 |
| **微观嵌套与补 0** | `macro.nest(micro)` 或 `refine_with()` / `tensor_product()` | `logical_product` + `complement` | 将微观 Layout 填入块内 `0` 维度，统计 `@reg` 微观体积，并按全局步长（从右往左 / 主序轴优先）自动填补宏观剩余的 `0`。 |
